# design-security

セキュリティの設計は、何を守るかを決め、層ごとに守りを考え、それを一つの優先順位に並べ直す仕事である。この playbook は、その順序を組み立て、最後の並べ直しを持つ。並べ直しを各層に任せると、各層は自分の層で止められることだけを書き、層をまたいで成り立つ攻撃と、層どうしが「相手が守る」と思い込んだ隙間が、どの資料にも載らないからである。

## 流れ

1. **何を守るかを決める。** decide-what-to-protect に、対象の資料と保存先を渡す。既に守るものの資料があれば、それを入力に深めるか、そのまま使う。守るものが決まるまで、層の分析へ進まない。守るものが決まっていない分析は、比べる物差しを持たないからである。
2. **当てはまる層を選ぶ。** 対象の構成から、ブラウザで動く部分、サーバーサイドの処理、インフラと運用のうち、どれがあるかを決める。無い層は呼ばず、無い理由を資料に一文書く。
3. **層ごとに分析する。** 選んだ層の入口に、守るものの資料、対象の資料、層ごとの保存先を渡す。層どうしは互いの結果に依存しないので、順序は問わない。各層の結論は、その入口の資料が持つ。この playbook は層の結論を書き直さない。食い違いを見つけたら、その層の入口への提案として返す。
4. **層をまたいで並べ直す。** 下の「並べ直しの判断」に従って、一本のセキュリティ設計の資料にまとめる。
5. **利用者と決める。** 並べ直しで残った費用とリスクの論点を、grill の公開入口で問う。

## 並べ直しの判断

**層をまたぐ脅威は、入口と止める場所を分けて書く。** たとえば、ブラウザから直接読むデータベースへの大量の読み取りは、入口がブラウザ、守りの規則がサーバーサイド、費用の停止がインフラにあり、その停止は全体を止める手段にもなる。一つの攻撃が各層でどう見え、どこで止まり、止めたことが別の守るもの（可用性）を壊さないかを、一続きで書く。各層の資料には、その層の部分しか載らないからである。

**隙間は、各層が他の層に期待していることを突き合わせて探す。** 層の資料が「この経路は別の層が守る」と書いた箇所を集め、その別の層の資料に実際に守りがあるかを確かめる。どちらにも無ければ隙間である。逆に、同じ守りを二つの層が別の答えで持っていれば、どちらの層が持つかを決める提案にする。

**優先順位は、失うものの大きさと、それが起きる見込みと、守りの費用で決める。** 守るものの資料の優先順位を物差しにし、一つの対策で複数の守るものを守れるものを先に置く。対策を選ぶときは、守る相手に合っているか、費用が守るものの価値に釣り合うか、少ない人手で続けられ利用者の使い方を壊さないかを確かめる。続かない対策は、入れた日から形だけになる。製品を足す前に、原因のコードと設定を直せないかを見る。

**予防だけでなく、気付くこと、止めること、戻すことを並べる。** いつかは破られる前提で、何が起きたら誰がどう気付き、何を止め、どこまで戻せるかを書く。戻せることは、復元を試して確かめるまで確定しない。

**受け入れるリスクは、利用者の決定として書く。** 採らない対策と残るリスクは、理由と、その決定を見直す条件と組にする。利用者が決めていない受け入れを、推奨のまま確定した決定として書かない。

## 利用者と決めること

公開前に入れる対策の範囲、費用のかかる対策の採否、残すリスクの受け入れは、利用者の決定である。並べ直しの結果から、答えで対策の一覧か優先順位が変わる論点だけを、推奨と理由を添えて grill の公開入口に題材として渡す。各層の入口がすでに問うた論点は、その決定を前提として使い、問い直さない。未決は、推奨を仮に置いたことが分かる形で資料に書く。

## 資料の形

冒頭に、最も危ない経路と、公開前に入れる対策の上位を言い切る。守るもの、層、狙われる場所を一枚に描いた全体図を早い位置に置き、どの経路の守りが薄いかを見せる。脅威の大きさは、起きやすさと影響で並べた図で示す。続けて、公開前に入れる対策（優先の順に、何を守るかと費用を添えて）、層をまたぐ脅威、気付く・止める・戻す備え、採らない対策と受け入れたリスク、確かめていないことを書き、各層の資料へのリンクを添える。資料は write-doc の公開入口に、素材と保存先を渡して保存する。

## 入力

対象のシステムの要件の資料、構成の資料、コードのどれか一つ以上の絶対パスと、資料を置くディレクトリの絶対パスを受け取る。既に守るものの資料や層の資料があれば、その絶対パスも受け取る。

## 止まるとき

この資料の結論は、公開前に入れる対策とその優先順位、受け入れたリスクである。decide-what-to-protect が守るものを決められずに止まったときは、同じ理由で止まる。層の入口が止まったときは、その層の分析が無いことと理由を資料に書き、その層に依存する並べ直しを未決にして進む。ほかの層の結論は、それだけで使えるからである。ただし、全ての層が止まったときは止まる。保存先が絶対パスで一つに決まらないとき、write-doc か grill が失敗したときも止まる。

## 返すもの

保存したセキュリティ設計の資料と、守るものの資料、層ごとの資料の絶対パス、公開前に入れる対策の上位、層をまたぐ脅威と見つけた隙間、利用者が決めたこと、推奨を仮に置いた未決、各層の入口への提案を返す。
